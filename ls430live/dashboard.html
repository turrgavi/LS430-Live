    Write actions

    Locked
    Clear trouble codes and turn off the check engine light
    • Only allowed with the engine off and ignition ON, car stationary. The app checks RPM and speed first.
    • Also erases freeze-frame data and resets emissions readiness. An inspection may fail until the car has been driven for a few days.
    • It doesn't fix anything. A real fault will bring the code back. Write the codes down first.
    • Every write is logged to logs/actions.log, and the lock re-engages after each one.

    Active tests

    Command parts directly: cooling fan, fuel pump, door locks…
    Waiting for recorded commands

    Toyota never published the commands behind active tests, and they differ by computer (engine, body, doors). Guessing could leave a part switched on or confuse a module, so this page only runs commands recorded from Techstream on your own car.

    Next step (about 20 minutes, in your Windows VM):

    1. Start a traffic recorder between Techstream and the Mini VCI. Claude will set it up.
    2. In Techstream, run each test you want, such as cooling fan, fuel pump, or door lock. Note the time you press each button.
    3. Send the recording to Claude. Each test is decoded and added here with its own on/off controls.

    Safety rules already built in for when tests arrive: write lock, engine state checks per test, an automatic "stop" command and time limit, and logging to actions.log.

    Customize

    Body settings: auto-lock, light timers, wireless unlock…
    Waiting for recorded commands

    Customization settings live in the body computers, which sit behind the gateway on Toyota's private body network. The commands for reading and changing them come from the same Techstream recording session as active tests.

    When added, every setting shows its current value read from the car. Changing one needs the write lock off and a confirmation, and the old value is saved so it can be restored with one click.
